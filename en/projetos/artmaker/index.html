Why it exists

Someone asked me for help making promo graphics for the products in her grocery store. If I made the graphics, she would always depend on me. So I built a tool that makes the job simple: she sets everything up the way she wants and gets the finished graphic at the end.

02

Problem, system, and proof

Problem

Every promo graphic would depend on someone who knew how to put it together.

System

A 1080×1920 deal flyer generator in WhatsApp Status format, in a single HTML file with Canvas. Everything is saved on the device itself.

Proof

33 tests

04

How it was built

Architecture

ArtMaker is a single index.html in plain JavaScript, with no framework, build, or server. The editor keeps everything in an estado object; on every change, the desenharEncarte function redraws the flyer on a 1080 × 1920 2D Canvas. The DOM-free rules, such as price parsing, contrast, and data validation, live in a block marked PURO, separate from the drawing code. Text and style go to localStorage, and photos go to IndexedDB.

Technical decisions

  1. A single file, on purpose

    I chose to ship the whole app in one index.html, so sending the file and opening it in a browser is enough. The default logo is embedded as WebP, because an external image opened straight from disk taints the canvas and the browser blocks the download. The CSP is set in a meta tag, with default-src 'none' and each inline script allowed by its SHA-256 hash; the only outside source is Google Fonts.

    View in code: README.pt-BR.md L161–164 README.pt-BR.md L174–177 index.html L9

  2. Same code draws preview, file, and thumbnails

    desenharEncarte takes the canvas context and options: a different context, colors, or region. That way, the same function draws the live preview, the exported PNG (without editing hints such as "Enter the price"), the thumbnails of the 8 palettes, and those in the Style tab, which show only a crop of the flyer. There is no second rendering engine to keep in sync.

    View in code: index.html L1443–1446 index.html L2126–2134 index.html L3107 index.html L3203–3214 index.html L3255–3259

  3. Contrast fixed without changing the color

    People choose colors freely, so a combination can make text unreadable. contraste follows the WCAG formula, and ajustarCor keeps the chosen hue and darkens or lightens it only as much as needed to reach the minimum: 3:1 in general and 4.5:1 for small text. The drawing applies this correction to the name, the price, the title, and the struck-through price, and the Colors tab warns when it kicks in.

Challenge

Autosave without losing work

The flyer saves while you edit: the state without images goes to localStorage half a second after the last change, and photos go to IndexedDB, each with its own id, in a per-key queue so the latest change always wins. Moving a product doesn't rewrite any photo. If another tab saves the flyer, the storage event makes this one stop saving and show a warning. Data that is saved or opened goes through normalizarDados before it is loaded.

Testing

There are 33 tests with node --test, with no dependencies. Since the app is a single file, the test reads index.html, cuts out the PURO block, and runs it in an isolated node:vm context: 31 tests cover price, discount, contrast, dates, file name, and project validation. The other 2 recompute the CSP hashes of index.html and 404.html. GitHub Actions runs everything on every push, on Node 22.
