01

Por que existe

Uma pessoa me pediu ajuda para fazer as artes de promoção dos produtos do mercado dela. Se eu fizesse as artes, ela sempre dependeria de mim. Por isso fiz uma ferramenta que simplifica a criação: ela configura tudo como quiser e recebe a arte pronta no final.

02

Problema, sistema e prova

Problema

Cada arte de promoção dependeria de alguém que soubesse montar.

Sistema

Gerador de encartes de ofertas 1080×1920 no formato do Status do WhatsApp, num único arquivo HTML com Canvas. Salva tudo no próprio aparelho.

Prova

33 testes

node --test no GitHub Actions. Conferidos em 9/11/2026.

04

Como foi construído

Arquitetura

O ArtMaker é um index.html só, com JavaScript puro, sem framework, build ou servidor. O editor guarda tudo num objeto estado; a cada mudança, a função desenharEncarte redesenha o encarte num Canvas 2D de 1080 × 1920. As regras sem DOM, como leitura do preço, contraste e validação dos dados, ficam num bloco marcado PURO, separado do desenho. Textos e estilo vão para o localStorage, e as fotos, para o IndexedDB.

Ver no código: index.html L1206–1208 index.html L1443–1447 index.html L2126–2166 index.html L3255–3261 README.pt-BR.md L214–226

Decisões técnicas

  1. O app inteiro num index.html

    Escolhi entregar o app inteiro num index.html, para que baste mandar o arquivo e abrir no navegador. A logo padrão vai embutida em WebP, porque uma imagem externa aberta direto do disco contamina o canvas e o navegador bloqueia o download. A CSP vai por meta, com default-src 'none' e cada script inline liberado pelo hash SHA-256; de fora, só o Google Fonts.

    Ver no código: README.pt-BR.md L161–164 README.pt-BR.md L174–177 index.html L9

  2. O mesmo código desenha prévia, arquivo e miniaturas

    O desenharEncarte recebe o contexto do canvas e opções: troca de contexto, de cores e de região. Assim, a mesma função desenha a prévia ao vivo, o PNG exportado (sem marcas de edição como "Informe o preço"), as miniaturas das 8 paletas e as da aba Estilo, que mostram só um recorte do encarte. Não há um segundo motor de desenho para manter em sincronia.

    Ver no código: index.html L1443–1446 index.html L2126–2134 index.html L3107 index.html L3203–3214 index.html L3255–3259

  3. Contraste corrigido sem trocar a cor

    A pessoa escolhe as cores livremente, então uma combinação pode deixar o texto ilegível. O contraste segue a fórmula do WCAG, e o ajustarCor mantém o matiz escolhido e escurece ou clareia só o necessário até atingir o mínimo: 3:1 no geral e 4,5:1 em texto pequeno. O desenho aplica essa correção ao nome, ao preço, ao título e ao preço riscado, e a aba Cores avisa quando ela entra.

    Ver no código: index.html L1287–1313 index.html L1755 index.html L1989–1990 index.html L2060 README.pt-BR.md L102–104

Desafio

Salvar sozinho sem perder o trabalho

O encarte salva enquanto se edita: o estado sem imagens vai ao localStorage meio segundo depois da última mudança, e as fotos vão ao IndexedDB, cada uma com um id próprio, numa fila por chave, para a última mudança sempre vencer. Mover um produto não regrava foto. Se outra aba grava o encarte, o evento storage faz esta parar de salvar e avisar. Dados salvos ou abertos passam pelo normalizarDados antes de entrar.

Ver no código: index.html L2176–2213 index.html L2215–2260 index.html L1419–1441 README.pt-BR.md L119–126

Testes

Os 33 testes rodam com node --test, sem dependências. Como o app é um arquivo só, o teste lê o index.html, recorta o bloco PURO e o roda num contexto isolado do node:vm: são 31 testes de preço, desconto, contraste, datas, nome do arquivo e validação de projetos. Os outros 2 recalculam os hashes da CSP do index.html e do 404.html. O GitHub Actions roda tudo a cada push, em Node 22.

Ver no código: puro.test.mjs L1–17 puro.test.mjs csp.test.mjs testes.yml
